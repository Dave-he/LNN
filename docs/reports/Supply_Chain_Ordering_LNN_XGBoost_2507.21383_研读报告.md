## 2. 核心问题

论文要解决的是一个**运营决策级**问题：

> 在一个四层供应链（消费者 → 零售商 → 分销商 → 制造商）里，**每天**决定各层订多少货，使得**累计利润**最大、同时**牛鞭效应**（上游订单波动被逐级放大）被压住。

拆开看作者的论证链（§1、§2）：

1. **经典方法不够**。移动平均（SMA）无法应对持续变化的行情（§1）。
2. **各 ML 方法各有短板**。LSTM 计算重、超参敏感；RL 试错成本高、样本需求大；XGBoost 静态、时序建模弱（§1）。
3. **LNN 看起来正好补位**。LNN 神经元少（"typically only tens"，§1）、计算成本低、对噪声鲁棒、适合边缘部署（§1 引 Hasani 2020/2022；§2.1 引 CfC 闭式解"快 1~5 个数量级"）。
4. **所以做混合**：LNN 做**局部动态特征提取**，XGBoost 做**全局优化**，两者合成一个预测器；预测器输出喂给一个**逐日利润最大化下单搜索**（§3.4）。
5. **研究问题**（§1 原文）："How does the LNN+XGBoost hybrid model reduce the bullwhip effect and increase cumulative profit through local and global synergy?"

**必须先说清的口径问题**（下文反复用到）：作者对"LNN"的定义，与本仓主线里的 LNN / LTC / CfC **不是同一个东西**。本文实现的"液态神经元"是一个**泄漏积分器 + 显式 Euler 的手写混合式**（§3.4.1），既不是 Hasani 2020 的 LTC 隐式 Euler，也不是 Hasani 2022 的 CfC 闭式解；而 CfC 那个"快 1~5 个数量级"的卖点被本文原封不动地搬来给"低计算成本"背书，**但本文根本没有用闭式解**（见 §3.3）。

## 3. 方法论与核心思路

### 3.1 数据：完全是作者造出来的合成序列

§3.1 + §4.2 给出消费者需求：

$$D(t) = 50 + 20\sin\frac{2\pi t}{90} + 5\sin\frac{2\pi t}{7} + N(0,\,3)$$

- 三个分量分别是**常数基线**、**季度季节**（周期 90 天）、**周季节**（周期 7 天）、**高斯噪声**（σ=3）。
- 需求截断为非负；随机种子固定为 42~51（10 次运行）。
- 模拟时长 1095 天（3 年），**训练段 = 前 219 天（20%）**，**验证段 = 后 876 天（80%）**。
- 初始库存 100 单位/层；补货提前期 1 天。

**复算（本人）**：按上式重放 1095 天，得

| 量 | 复算值 |
|---|---|
| mean(D) | 50.07 |
| std(D) | 14.96（解析值 √(20²/2 + 5²/2 + 3²) = 14.58，吻合） |
| min / max | 18.85 / 79.93 |

**方法学含义（本人推断）**：这条序列的**可预测部分（两个正弦）是 t 的确定性函数**，噪声只有 σ=3。因此对"预测下一天 D(t)"这个任务，**真正的信息瓶颈是 3 单位的噪声**，而季节/周相可以由 $\sin(2\pi t/90)$、$\sin(2\pi t/7)$ 精确给出。这不是一个"难"预测问题；它更接近"给定一个近乎解析的信号加小噪声"的问题。这直接决定了 §5.6 的结论：**本文的结论不能外推到任何真实需求序列。**

### 3.2 四层结构与需求上传

§3.2：$D_i(t) = O_{i-1}(t),\ i=1,2,3$，即零售商的需求 = 消费者的订单，分销商的需求 = 零售商的订单，制造商的需求 = 分销商的订单。**经典牛鞭效应的传递结构**（beer game 式）。

### 3.3 特征工程（10 维）

§4.2：当期需求、滞后订单 (t−1, t−2)、滞后库存 (t−1, t−2)、滞后销量 (t−1)、近 5 天订单标准差、近 5 天需求标准差、季节指示 $\sin(2\pi t/90)$、归一化时间 $t/1095$。共 10 维，用 `MinMaxScaler` 归一化到 [0,1]，10 天滑动窗口。

**本人标注的两个风险点**：

1. **MinMaxScaler 的拟合窗口未说明**。若在全 1095 天上拟合再应用到训练段，就是一次**未来信息泄漏**（用未来的极值缩放过去）。论文只说"Features are normalized ... using MinMaxScaler"，未说明 fit on train only。**这是 sklearn 最经典的坑**，且对树模型影响尤大。
2. **$t/1095$ 这个绝对时间索引对树模型是风险特征**。XGBoost 可以把"训练段的时间位置"当成类别特征记忆（训练段的确定性季节水平被学成"t 小 ⇒ 需求中位数"），在验证段外推时会系统性偏移。季节指示 $\sin(2\pi t/90)$ 本身是**提前已知**的，这不算泄漏；问题在 $t/1095$。

### 3.4 五个模型与"LNN 在系统里的确切角色"

**这是本篇最需要讲清楚的一节。** 论文比较的五个模型（Table 1）：

| 模型 | 论文给的配置 |
|---|---|
| **LNN + XGBoost 混合** | LNN：64–1024 神经元（步长 64）、Xavier 初始化、**自适应泄漏率（基准 0.5，按输入波动调整）**、**τ = 1**、AdamW（lr 1e-5~1e-3）；XGBoost：**回归器建在 LNN 输出状态展平后的特征上**，100–300 棵树、深度 3–7、lr 0.01–0.3 |
| 独立 XGBoost | 直接吃 10 维工程特征 |
| LSTM | 64–256 隐单元、1–3 层、7 天预测 horizon、Adam、梯度裁剪 0.5 |
| Transformer | d_model 64–256、2–8 头、1–3 层、dropout 0.1、裁剪 0.1 |
| DQN | 64–256 隐单元、replay buffer 20 000、ε-greedy 1.0→0.1、奖励含收入/成本/服务水平 |

**LNN 的确切角色（三层，缺一不可）**：

1. **特征变换器**：把 10 维工程特征 + 10 天窗口，经一个"液态"循环网络产出**状态序列**，展平后作为 XGBoost 的输入特征。
2. **不是决策者**：真正的下单量由 §3.4.3 / §4.3 的**逐日利润最大化搜索**决定，LNN 完全不参与。
3. **不是唯一的预测器**：最终预测值来自**第二个 XGBoost 回归器**。也就是说论文里叫 "LNN" 的那个模型，**输出层其实是 XGBoost**；LNN 只是一个前置的循环特征编码器。

**由此产生一个结构性混淆（本人推断，重要）**："LNN vs 独立 XGBoost" 这一对比**不是架构对架构**，而是**"多了一个 64–1024 神经元的循环网络 + 一层树" vs "只有一层树"**。前者多出的容量本身就是混淆项。论文在 §4.3 进一步用 SHAP 把关键特征的贡献归给"LNN 的局部特征提取"，但 §3.6 已写明 **SHAP 用的解释器是按"最终是不是树模型"选的**：混合模型末端是 XGBoost → 用 `TreeExplainer`。**那么这些 SHAP 值解释的是"XGBoost 如何看待 LNN 的输出状态"，而不是"LNN 为什么好"**；论文把前者读成后者，属于因果越界。§5.2 会给出这个越界的具体后果。

### 3.5 下单决策（本篇最关键、也最含糊的一段）

**§3.4.3 写的是**：

$$O_i(t) = \text{batch\_size}\cdot\left\lceil \frac{O_i(t)}{\text{batch\_size}} \right\rceil$$

候选区间写作 $[\hat D_i(t),\ \text{max\_inventory} - I_i(t-1)]$，其中 `max_inventory` **全文未给出取值**。

**§4.3 实际执行时写的是**（与上不一致）：

- 候选订单区间：**从预测需求到 1.5×近 10 天平均需求 − 当前库存**，**步长 80 单位**；
- 利润 = 收入 − 采购成本 − 持有成本 − 缺货成本；
- 取利润最大的那个订单，**调整到最接近的 16 的倍数**（"nearest multiple of 16"）；
- 安全库存 $SS = \text{safety\_stock\_base} + 1.0\times\sigma_D(t-10:t)$（基准 5~20，是被 Optuna 调的参数之一）；
- 预测：7 天 horizon，**线性加权 1.0 → 0.5**，再**指数平滑 α = 0.3**。

**复算与本人推断（这一节决定了整篇的可复现性）**：

**(a) 候选区间在论文给定的初始条件下是空集。**
按 §4.3 的上界 $1.5\times\overline D_{10} - I(t-1)$：初始 $I=100$、近 10 天均需求 ≈ 57.4，上界 ≈ $1.5\times57.4-100 = -13.9$；下界 $\hat D_i(t) \approx 50$。**上界 < 下界 → 区间为空。** 复算：

| 库存 $I(t-1)$ | 上界 $1.5\bar D_{10}-I$ | 与下界 ($\hat D\approx50$) 关系 |
|---|---|---|
| 100（初始） | −13.9 ~ −25 | **空/倒置** |
| 60 | 15 | **空/倒置** |
| 40 | 35 | **空/倒置** |
| 20 | 55 | 非空 |
| 0 | 75 | 非空 |

也就是说，**在库存降到 20 以下之前，论文写的下单搜索没有任何候选值**。论文没有说明空区间/倒置区间如何处理（取下界？取上界？直接不下单？）。这意味着**读者无法从论文复现出论文的实验**。

**(b) 区间下界 = 预测值 ⇒ 策略永远不能"订少"。**
候选集从 $\hat D$ 起步、步长 80 向上，所以**订單量只能等于或高于预测值**。一个系统性高估的模型被迫超订，一个系统性低估的模型被迫少订；**这个规则无法奖励保守性**。而步长 80 相对日均需求 50 而言是 **160% 的网格粒度**，实际可选项极少（基本是"订 $\hat D$"与"订 $\hat D+80$"两档）。

**(c) 批量取整两种口径不一致，且差一个系统性偏置。**
§3.4.3 是 **ceil（向上取整）**，§4.3 是 **nearest（四舍五入）**。复算示例：

| 原始订单 | §3.4.3 (ceil→16) | §4.3 (nearest→16) |
|---|---|---|
| 48 | 48 (+0) | 48 (+0) |
| 50 | **64 (+14)** | 48 (−2) |
| 64 | 64 (+0) | 64 (+0) |
| 71 | **80 (+9)** | 64 (−7) |

ceil 口径在订单量对 16 均匀分布时**期望偏置 +8 单位/次**；876 天 × 3 层 ⇒ 累计多订 **21 024 单位**。这在三层链上会**逐级放大**（牛鞭效应），直接改变 Figure 3 的结论。论文两处口径不一致且未说明用的是哪个 ⇒ **图 3 的牛鞭对比不可复现**。

**(d) 安全库存（一个被 Optuna 调的参数）没有出现在决策式里。**
§4.3 明确列出"safety stock base (5–20)"是**被调优的超参**，但 §4.3 的候选区间与利润公式中**都不含 SS 项**；§3.4.2 的 $SS_i(t) = SS_{\text{base}} + SS_{\text{factor},i}\sigma_{D_i}(t)$ 也没有说它如何影响下单量。而且 §4.3 的 SS 公式把 $\text{SS}_{\text{factor}}$ **取成了对所有层都等于 1.0**，与 §3.4.2 声称的"层特定系数"矛盾。**按论文印刷的规则，被调的 safety_stock_base 对结果没有影响。**

**(e) 目标变量自相矛盾：预测"库存"还是预测"需求"？**
- §3.4.1："To predict **inventory levels**, a diverse set of machine learning models is utilized"；§3.4.1 末："Each model processes the engineered features to forecast **inventory levels** over a specified horizon"。
- §4.3："**Demand forecasting**: Models predict demand for the next 7 days"；候选区间下界："the **forecasted demand**"。
- §3.7 指标："Prediction MAE: Mean absolute error of **inventory predictions**"。

**同一个模型被同时说成"预测库存"和"预测需求"**，而这两个量在物理上完全不同（库存 ≈ 需求 + 到货 − 销量）。若模型学的是库存，却被当成需求下限来下单，**量纲上就说不通**。这是全文最需要读者自行补全、而论文没有补全的一处。

**(f) 利润最大化搜索的"预言机"问题（最关键的公平性隐患）。**
§3.4.3 说利润由"Revenue（由销量决定，受**库存与需求**约束）、采购成本、持有成本、缺货成本"算出。**论文从未说明这里的"需求"是预测值 $\hat D$ 还是仿真器里的真实实现值 $D(t)$。**

- 若用**实现值**：则每一步的"利润最大化"是在**已知当天真实需求**的前提下做的**一步前瞻最优**（在仿真器里当然拿得到）。此时预测模型对最终利润的影响被压缩到只剩三处通道：候选区间的**下界** $\hat D$、安全库存、以及预测的偏置方向。**那么"哪个模型更好"主要测的是"谁的预测偏置方向更有利"，而不是"谁预测得更准"。**
- 若用**预测值**：则"利润"是一个基于预测的**近似目标函数**，而实际利润仍由实现值决定，两者之间存在模型误差的耦合。

两种读法下，"LNN 排第一"的含义完全不同，而**论文没有报告是哪种**。这一条无法从论文本身解决，**是引用本文时必须标注的保留**。

### 3.6 超参优化

§3.5 + §4.3：Optuna + TPE sampler，**每个模型每次运行 10 个 trial**，目标是**最大化制造商层（layer 3）的累计利润**：

$$\text{Objective} = \sum_{t=1}^{T}\text{Profit}_3(t)$$

**本人推断的两个问题**：

1. **10 个 trial 与搜索空间严重不匹配。** 可调项含：神经元数 16 档（64~1024 步长 64）、XGBoost 树数（100~300）、深度（3~7）、batch（4~8 步长 4）、epochs（50~100；DQN 100~200）、安全库存基准（5~20）、以及连续的学习率（1e-5~1e-3 / 0.01~0.3）。仅离散项就有 16×5×5×2×2×16 ≈ **2.6×10⁴** 组合，再乘两个连续维度。**10 次抽样覆盖的搜索空间份额 < 0.01%**，TPE 的代理模型在 10 个样本上几乎没有可建模的信息 ⇒ **"经过 Optuna 调优"在本篇里实质等价于"几乎随机地抽了 10 组超参"**。
2. **调优窗口未说明 ⇒ 极可能是"用报告集调参"。** 论文只说明**下单优化循环发生在验证段（第 220~1095 天）**，而 Optuna 目标需要"累计利润"⇒ 目标必须跑这个循环。若目标跑在验证段，那么**超参是在"报告所用的同一段数据"上被挑出来的**（典型 test-set tuning）。若目标跑在训练段（219 天），论文必须定义训练段的下单循环 —— 未定义。**两种可能都指向同一个问题：调优口径不可核查。** 另需注意**目标（layer 3 累计利润）与报告指标（三层加权综合分）不是同一个量**，调优并未直接优化被报告的指标。

### 3.7 评估口径

- 效率：$Efficiency_i(t) = Profit_i(t) / TheoreticalProfit_i(t)$，其中 $TheoreticalProfit_i(t) = D_i(t)(P_i - C_i)$（完美需求满足、无持有/缺货成本时的上限）；再取 7 天移动平均。
- 综合分：五个指标（累计利润 0.5、库存周转 0.2、服务水平 0.2、成本 −0.1、预测 MAE −0.1），各指标先做 **Min-Max 归一化**（**全局极值取自所有模型、所有运行、所有层**），层内加权求和，再按 零售商 0.4 / 分销商 0.3 / 制造商 0.3 聚合。
- 统计：成对 t 检验、Tukey HSD、ANOVA，各 10 次运行。

**复算（本人）—— 综合分不是"归一化"的量**：

- 默认权重之和（有符号）= 0.5+0.2+0.2−0.1−0.1 = **0.7**；**正权重部分最大 0.9，负权重部分最小 −0.2**。
- LNN 的 0.6297 ÷ 0.9 = **69.97%**（自定义权重：0.5930 ÷ 0.8 = **74.13%**）。
- 但**更关键**：Min-Max 归一化用的是**跨全部模型/运行/层的全局极值**，所以"最好的模型在该指标上必然拿 1.0"。**综合分是模型之间的相对排序统计量，不携带任何绝对质量含义**，不能读成"LNN 达到了 63% 的最优水平"。

## 4. 核心公式提取（附本人复算）

### 4.1 论文印刷的 LNN 神经元更新式（§3.4.1）

$$s_t = (1-\alpha_t)\cdot s_{t-1} + \alpha_t\cdot a_t + \frac{dt}{\tau}\cdot(-s_{t-1}+a_t)$$

其中 $s_t$ 为神经元状态、$\alpha_t$ 为自适应泄漏率、$a_t$ 为激活输出、$\tau$ 为时间常数、$dt$ 为时间步。

**本人复算（代入论文自身参数：日步长 $dt=1$、$\tau=1$）**：

$$s_t = (1-\alpha_t)s_{t-1} + \alpha_t a_t + (-s_{t-1}+a_t) = \boxed{-\alpha_t\, s_{t-1} + (1+\alpha_t)\, a_t}$$

**数值验证（本人脚本，$a_t \equiv 1$，初值 0）**：

| $\alpha$ | 打印式 $s_t$ 序列 | 手算 $-\alpha s_{t-1}+(1+\alpha)a_t$ | 一致？ |
|---|---|---|---|
| 0.1 | 1.1, 0.99, 1.001, 0.9999, 1.0, 1.0 | 同左 | ✅ |
| 0.5 | 1.5, 0.75, 1.125, 0.9375, 1.0312, 0.9844 | 同左 | ✅ |
| 0.9 | 1.9, 0.19, 1.729, 0.3439, 1.5905, 0.4686 | 同左 | ✅ |

**这个化简的三个后果（本人推断）**：

1. **状态项的符号被翻转**。齐次解变成 $s_t = (-\alpha)^t s_0$ —— **逐步变号**。标准泄漏积分器 $s_t=(1-\alpha)s_{t-1}+\alpha a_t$ 的特征根是 $+(1-\alpha)$（恒正）；本文打印式在 $dt/\tau=1$ 时特征根是 $-\alpha$（**变号**）。换句话说，论文声称的"时间常数 $\tau=1$"在它自己的式子里**不成立**：等效衰减率变成 $\alpha$（而不是 $1-\alpha$），**有效时间常数 $\tau_{\text{eff}} = -1/\ln\alpha$**：$\alpha=0.5$ 时 $\tau_{\text{eff}}=1.44$ 步，$\alpha=0.1$ 时 0.43 步，$\alpha=0.9$ 时 9.49 步。
2. **输入增益被放大到 $1+\alpha$**（基准 $\alpha=0.5$ 时是 **1.5**，而标准泄漏式只有 0.5），即进入状态的是激活的 **1.5 倍**。
3. **稳定窗口变窄**。打印式要求 $|\!-\alpha\!|<1 \Rightarrow \alpha<1$；标准泄漏式 $s_t=(1-\alpha)s_{t-1}+\dots$ 的稳定条件是 $\alpha<2$。而论文明确说 $\alpha_t$ 是"**按输入波动自适应调整**"的（基准 0.5）—— 波动越大 $\alpha$ 越大，**一旦 $\alpha_t$ 被推到 ≥1，打印式就发散，而标准泄漏式到 1.9 还稳定**。也就是说，**这个"自适应"机制恰好作用在最脆弱的方向上**（若实现与公式一致）。

**必须同时说明的三点**（避免误伤）：

- 上述结论**仅针对论文印刷出来的公式**。代码不公开，**实际实现可能与公式不同**（例如实现里 `dt/τ` 取的是别的时间尺度、或 `a_t` 已经被归一化过）。
- 本式**不是** Hasani 2020 的 LTC 隐式 Euler（$s_t = s_{t-1} + \frac{dt}{\tau}\left(-\frac{s_{t-1}}{\tau} + f(\cdot)\right)$，需解一个线性方程），也**不是** Hasani 2022 的 CfC 闭式解。它更像"泄漏积分器 + 一步显式 Euler"的**手工混合**，两种机制被叠加了。
- §2.1 专门引用了 CfC "1~5 个数量级加速、8000 样本上快 220 倍"来说明 LNN 的效率优势 —— **而本文根本没用闭式解**，所以这条引用**不能用来支持本文的效率主张**（何况本文也没测效率，§3.8）。

### 4.2 需求生成（§3.1）

$$D(t) = 50 + 20\sin\frac{2\pi t}{90} + 5\sin\frac{2\pi t}{7} + N(0,3),\qquad D(t)\ge 0$$

见 §3.1 的复算（mean 50.07、std 14.96、min 18.85、max 79.93）。

### 4.3 安全库存（§3.4.2 / §4.3，两处不一致）

$$SS_i(t) = SS_{\text{base}} + SS_{\text{factor},i}\cdot\sigma_{D_i}(t)\qquad(\S 3.4.2)$$

$$SS = \text{safety\_stock\_base} + 1.0\times\sigma_D(t-10:t)\qquad(\S 4.3)$$

### 4.4 效率与综合分（§3.7）

$$Score_{\text{layer}} = w_{\text{profit}}\cdot profit + w_{\text{turnover}}\cdot turnover + w_{\text{service}}\cdot service + w_{\text{cost}}\cdot cost + w_{\text{mae}}\cdot mae$$

$$TotalScore = 0.4\,Score_{\text{retailer}} + 0.3\,Score_{\text{distributor}} + 0.3\,Score_{\text{manufacturer}}$$

**复算**：权重和有符号和 0.7、正权重和 0.9、负权重和 −0.2；LNN 0.6297 = 理论上限 0.9 的 69.97%。且因归一化用全局极值，**该分数是相对排序量而非绝对量**（§3.7 末）。

### 5.6 公平性总评：本文**没有跑**它自己论证的那个对比

论文的整个动机是"**经典方法（移动平均）不够用 → LNN 能补位**"（摘要、§1）。但实验的五个模型是 LNN+XGBoost / XGBoost / LSTM / Transformer / DQN —— **SMA、EOQ、(s,Q)、base-stock、ARIMA，一个都没有**。

也就是说，**本文既不能支持、也不能反驳"LNN 优于经典模型"这个命题**：它根本没有做这个对比。§2.6 还专门讨论了 EOQ / 鲁棒优化（Bertsimas–Thiele）/ 库存管理教科书（Silver et al.）作为理论基础，但都只停留在"文献综述"，不进实验。

**同台比较中还存在三处系统性不对称（本人推断）**：

1. **容量不对称**：混合模型 = 64–1024 神经元的循环网络 **+** 100–300 棵树的 XGBoost；独立 XGBoost = 只有 100–300 棵树。**这不是架构对架构，是"更大的管线"对"更小的管线"。**
2. **基线调优不对称**：作者自己承认 RL 基线没调好（§5 讨论，建议改用 DDPG/PPO）；LNN 侧却拿到了 Optuna + TPE。而 Optuna 只有 10 个 trial（§3.6），**对所有模型都一样地"几乎没调"** —— 这一点倒是对称的，但 LNN 侧的超参空间更大。
3. **SHAP 归因越界**：混合模型的末端是树模型 → 走 `TreeExplainer`（§3.6），所以 Figure 6 的重要性排序解释的是**"XGBoost 如何使用 LNN 的输出状态"**，论文却把它读成 **"LNN 的局部特征提取在起作用"**（Table 2 的 "Demand and Order Prioritization" 行原文："This precision, driven by **LNN's local feature extraction** and XGBoost's global optimization"）。**这是从"树用了一个有用的输入"推出"前置网络有用"的因果越界。** 且 §2.1 引用 "Smith and Doe (2022) combined LSTM with XGBoost"（"our code's hybrid approach"）——**混合思路本身不是新意**，论文的新意主张是"LNN + XGBoost"这一特定组合。

**综合：本文的模型对比是"同台但不同容量"；它的统计结论只支持"四个监督/学习模型 > 一个没调好的 RL"；它自己拒绝了"前三名有差异"。**

## 6. 局限性与未来展望

### 6.1 作者自陈的局限

§5 与结论里作者自己承认的：

- RL 基线表现差，原因是"高维动作空间 + 稀疏奖励"，建议未来试 **DDPG / PPO**（即承认基线未调好）；
- 未来工作应把框架扩展到**真实数据集**（如"大型物流企业的历史数据"）——**即承认当前的合成数据限制了泛化性**；
- 未来可加入**实时数据流、不确定性因子**，以及**环境可持续性、成本效益分析**等新指标。

值得注意的是：**作者自己把"用真实数据"列为未来工作，却已经在摘要与结论里把结论说成了"LNN + XGBoost 是 leading solutions"**。

### 6.2 本人识别的隐含局限（作者未讨论）

### 6.3 未来方向（作者提及 + 本人建议）

作者已提：真实数据、实时流、不确定性因子、可持续性指标、DDPG/PPO。

**本人补充的建议（按性价比排序）**：

1. **先修可复现性，再谈结论**：把候选区间、批次取整口径、SS 的接入点、目标变量（库存 or 需求）写成唯一的一套自洽规则，并公开代码与合成数据的生成脚本。**在此之前，本文的任何排名都不可引用。**
2. **补齐经典基线**：至少加 SMA / EOQ / base-stock / (s,Q) / ARIMA，否则"LNN vs 经典"这一核心命题仍无答案。
3. **把牛鞭效应变成一个数**：用 $BV = \mathrm{Var}(O)/\mathrm{Var}(D)$ 或 Beer-game 经典比值，逐层报告，并给出置信区间。
4. **做真正的混合消融**：同一管线里比较 (a) 仅工程特征 → XGBoost，(b) 工程特征 + LNN 状态 → XGBoost，(c) 仅 LNN 端到端，(d) 独立 LSTM/Transformer 的同类混合。只有 (b) vs (a) 的差值才能归因给 LNN。
5. **修统计设计**：n=10 的 t 检验功效不足；建议改用逐日配对 bootstrap 或 Diebold–Mariano 式的预测损失比较，并**对全部 10 个模型对做多重比较校正**（Holm），而不是只报对 RL 的 p 值。
6. **用真实的 $\tau$ 语义**：若要走 LTC 路线，应采用 Hasani 2020 的隐式 Euler（需解线性方程）或 CfC 闭式解（与 §2.1 的效率卖点对齐），并**显式标注 dt/τ 的取值**；本报告 §4.1 已给出：本文印刷式在 $dt/\tau=1$ 时退化为变号递推 $s_t=-\alpha s_{t-1}+(1+\alpha)a_t$，其有效时间常数是 $-1/\ln\alpha$ 而非 $\tau$。

## 7. 对本仓的意义

**定位：可作为「LNN 在长尾 OR/工业任务上有过一篇应用型尝试」的留档，证据强度低，不构成任何优越性证据。**

- ✅ **可借鉴的（方法论层面）**：
  - **"局部动态编码 + 全局树优化"的分工叙述**是清晰的，可以借用到本仓的多任务场景：把连续时间状态当作**特征**，让树模型/线性头去吸收非平滑的交互。本仓 `lnn/core/` 里的 CfC/LTC 变体若要接下游任务，可参考这种"液态头 + 表格头"的接缝。
  - **本报告 §4.1 的一个具体结论值得本仓记住**：**当一个"液态神经元"写成 $(1-\alpha)s_{t-1}+\alpha a_t + \frac{dt}{\tau}(-s_{t-1}+a_t)$ 这种"泄漏 + 显式 Euler"混合式时，必须检查 $dt/\tau$ 的取值**。$dt/\tau=1$ 会把它变成 $s_t=-\alpha s_{t-1}+(1+\alpha)a_t$（变号 + 输入增益 1.5× + 稳定窗缩到 $\alpha<1$），而不是你以为的"标准泄漏积分器"。这是**公式抄写/拼接时的典型事故**，与本仓已有的教训同源（`docs/reports/LTC_NN_Implicit_Physics_Model_Recovery_2412.02215_研读报告.md` 中"Eqn 2 → Eqn 3 并非恒等变换"是同一类问题）。**本仓若在 `lnn/core/ltc.py` 一类的实现里对比不同 $\tau_{\text{eff}}$ 约定，必须锁死口径，否则会出现系统性偏置。**
  - **§5.6 的"混合模型 vs 独立基线不是架构对架构"是一条通用教训**：本仓若写 hybrid 对比（液态头 + 树头 vs 纯树），必须**报参数量/时延**，并做**只换一头的消融**，否则结论不成立。
  - **§3.8 的"卖点必须有测量"清单**（时延/FLOPs/参数量/方差比）可以直接当作本仓研读报告的自检项。

- ❌ **不可外推的**：
  - 不得据此声称「LNN 在供应链 / 运筹优化上优于经典模型」—— **本文没跑经典基线**（§5.6），这个命题在本文里是空的；
  - 不得据本文的 "0.6297" 说"LNN 达到了 63% 的最优水平"—— 该分数是**跨模型的相对排序量**，且权重和只有 0.7（§3.7）；
  - 不得把 Table 5 的 2,200,000 / 2,500,000 当作**实测**的累计利润（§5.3 第 5 点：15 个数值全为 10 万整数倍 + 数据不公开）；
  - 不得引用本文的"减少牛鞭效应"—— **全文无量化指标**（§5.4）；
