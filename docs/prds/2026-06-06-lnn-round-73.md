# PRD-73 — CfC vs DSS/S4/Mamba head-to-head on Canonical Reproducible Suite (round 73)

> **Selected** (round 73, 2026-06-06): 直接对应 deep-research 报告 §3.4 + §3.6 + §5 P1, 是 round 72 catalog 干净后的自然下一步。1-2 个 backbone × 1-2 个 dataset × 3 seed 的真实数字即可填补 2025-2026 LNN-vs-SSM 实证空白。

## 目标

在 4 个可复现基准 (sMNIST, permuted-MNIST, seq-CIFAR-10, Mackey-Glass) 上跑 CfC vs DSS vs Mamba vs GRU 的 head-to-head 对比, 给出**明确可引用**的 accuracy / NLL / params / wall-clock 表格, 填补 deep-research 识别的 2025-2026 LNN-vs-SSM 实证空白。

## 用户故事

- As a LNN 研究者, 我希望直接看到 CfC 在标准时序基准上 vs Mamba/SSM 的实际 delta, 这样写新论文 related work 时有具体数字可引。
- As a 边缘工程师, 我想知道在小 hidden (16-128) + 短序列 (<1000) 配置下, CfC 和 Mamba 哪个更适合 Jetson / MCU 部署, 这样选型有依据。
- As a 复现者, 我希望 4 个基准的 3-seed 复现脚本和 JSON 都存在, 这样别人能直接 verify 或 extend。
- As a 诚实的实验者, 我希望即使结果是 "Mamba/GRU 全面击败 CfC" 也能完整记录, 不隐瞒负结果, 避免 round 71 之前的 catalog 偏向 vendor claim 的问题。

## 风险

- **Mamba 实现复杂度**: selective scan 用纯 Python 写极易 O(T·D²), 需谨慎实现; 序列长度 ≤ 1000, hidden ≤ 128, 实际可行。Viterbi-style scan 一旦写对就是 O(T·D)。
- **数据集下载**: sMNIST / psMNIST 需 torchvision, seq-CIFAR 需自己拼, Mackey-Glass 仓库已有 (`scripts/ablation_lnn_vs_lstm_timeseries.py`)。需检查仓库内是否已缓存。**round 73 优先 Mackey-Glass** (已有, 不需要下载), sMNIST 作为 stretch goal。
- **seed 控制**: 不同 backbone 的 RNG seed 行为不同, 需在 `bench_suite.py` 中显式 `torch.manual_seed` + `np.random.seed` + `random.seed` 三件套。
- **诚实负结果**: Mamba 在 sMNIST 上通常 > 98%, 若 CfC < 95%, 报告必须诚实写, 不调整数字。
- **load_bearing assumption**: 假设 CfC 在长序列 (T > 500) 上有结构性优势, 短序列 (T < 100) 输给 Mamba/GRU 是预期内的负结果。**Mackey-Glass 默认 T = 1000 即可触发长序列优势窗口**。
- **DSS 复用 round 72 catalog**: `DiagonalSSMCell` 必须在 docs 中标注 2203.14343 是 DSS (非 Lockhart adaptive solvers), 引用 round 72 catalog 的 verdict。
